## Objective
Remediate DISA STIG WN11-CC-000110, which requires that printing over HTTP be prevented. Confirm the fix with an authenticated Tenable compliance scan and document a full fix → revert → re-apply validation cycle.

## Problem Statement
HTTP printing allows a client to send print jobs to internet-based printers over HTTP. This creates an outbound data path that can bypass network controls and exfiltrate document contents. Disabling it removes an unnecessary and monitorable egress channel. CAT II, mapped to NIST CM-7a (least functionality).

## Environment
- **Target:** Windows 11 Pro VM (`VirtualTest15`), private IP 10.0.0.10, Azure Cyber Range subscription
- **Scanner:** Tenable `LOCAL-SCAN-ENGINE-01`, authenticated credentialed scan
- **Audit policy:** DISA Microsoft Windows 11 STIG v2r7 (Windows Compliance Checks)

## Solution / Steps Taken
1. Confirmed the finding in the baseline authenticated scan — **Failed**.
2. Reviewed the Tenable Solution text: set `DisableHTTPPrinting` to `1` under the Windows NT Printers policy key.
3. Applied the fix via PowerShell (elevated):

```powershell
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Printers" -Force | Out-Null
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Printers" -Name "DisableHTTPPrinting" -PropertyType DWord -Value 1 -Force
```

4. Verified the value persisted, then re-scanned — **Passed**.

## Validation and Testing
| Scan State | Registry Value | Audit Result |
|---|---|---|
| Baseline | key absent / `0` | **Failed** |
| After fix | `1` | **Passed** |

Full fix → revert → re-apply cycle was demonstrated on WN11-CC-000315 as the representative methodology sample; this control is documented as remediation-confirmed. Scan timestamps captured in the Tenable History tab.

## Key Findings
- Registry path: `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Printers`
- Value: `DisableHTTPPrinting` (DWORD) — compliant when `1`
- Shares its parent key with WN11-CC-000100 (`DisableWebPnPDownload`); both values coexist in the same key.

## Security and SOC Relevance
Disabling HTTP printing removes an outbound channel that could be abused for data exfiltration disguised as a print job — the kind of low-visibility egress path a SOC wants closed and a VM Analyst flags during compliance review.

## Challenges and How I Solved Them
This control exposed a real remediation pitfall. My initial `Set-ItemProperty` for `DisableHTTPPrinting` reported success in the terminal but did not persist — a `Get-ItemProperty` check showed the value blank while the neighboring `DisableWebPnPDownload` (same key) held correctly. I re-applied using `New-ItemProperty -Force` and confirmed persistence with a delayed re-read (`Start-Sleep` then `Get-ItemProperty`) before rescanning. Root cause was an inconsistent commit from `Set-ItemProperty`; `New-ItemProperty -Force` reliably created and set the value.

## Lessons Learned
Never trust a configuration command's exit status alone — verify the actual system state at the source before validating. This is the difference between assuming a fix worked and proving it did, and it is exactly what prevents false "remediated" reporting in a real VM program.
