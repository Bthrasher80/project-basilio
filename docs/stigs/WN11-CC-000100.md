# WN11-CC-000100 — Downloading Print Driver Packages Over HTTP Must Be Prevented

**Date:** June–July 2026
**Stage:** Vulnerability Management — STIG Remediation
**Tools:** Tenable Vulnerability Management, PowerShell, Azure (Windows 11 VM)
**Benchmark:** DISA Microsoft Windows 11 STIG v2r7
**STIG-ID:** WN11-CC-000100 | **Vuln-ID:** V-253374 | **Rule-ID:** SV-253374r958478_rule
**Severity:** CAT II | **CCI:** CCI-000381 | **NIST 800-53:** CM-7a

## Objective
Remediate DISA STIG WN11-CC-000100, which requires preventing the download of print driver packages over HTTP. Confirm with an authenticated Tenable compliance scan.

## Problem Statement
Downloading print driver packages over HTTP allows unsigned or untrusted drivers to be pulled from internet sources. Malicious print drivers run in a privileged context and are a known code-execution vector. Disabling HTTP driver download forces drivers through controlled channels. CAT II, NIST CM-7a.

## Environment
- **Target:** Windows 11 Pro VM (`VirtualTest15`), private IP 10.0.0.10, Azure Cyber Range subscription
- **Scanner:** Tenable `LOCAL-SCAN-ENGINE-01`, authenticated credentialed scan
- **Audit policy:** DISA Microsoft Windows 11 STIG v2r7 (Windows Compliance Checks)

## Solution / Steps Taken
1. Confirmed the finding in the baseline authenticated scan — **Failed**.
2. Reviewed the Tenable Solution text: set `DisableWebPnPDownload` to `1` under the Windows NT Printers policy key.
3. Applied the fix via PowerShell (elevated):

```powershell
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Printers" -Force | Out-Null
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Printers" -Name "DisableWebPnPDownload" -PropertyType DWord -Value 1 -Force
```

4. Verified the value persisted, then re-scanned — **Passed**.

## Validation and Testing
| Scan State | Registry Value | Audit Result |
|---|---|---|
| Baseline | key absent / `0` | **Failed** |
| After fix | `1` | **Passed** |

Full fix → revert → re-apply cycle demonstrated on WN11-CC-000315 as the representative sample; this control documented as remediation-confirmed. Scan timestamps in the Tenable History tab.

## Key Findings
- Registry path: `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Printers`
- Value: `DisableWebPnPDownload` (DWORD) — compliant when `1`
- Shares its parent key with WN11-CC-000110 (`DisableHTTPPrinting`).

## Security and SOC Relevance
Blocking HTTP print-driver download closes a privileged code-execution path. Malicious drivers are a recurring theme in Windows attacks (e.g., PrintNightmare-class issues), so restricting driver sources is a meaningful hardening step a VM Analyst validates.

## Challenges and How I Solved Them
Because this control shares a registry key with WN11-CC-000110, I verified both values (`DisableHTTPPrinting` and `DisableWebPnPDownload`) with a single `Get-ItemProperty` after each change to confirm one edit never unintentionally affected the other. Both values coexist correctly at `1`.

## Lessons Learned
When multiple STIGs write to the same registry key, verify all affected values together after each edit — changing one value name does not disturb another, but confirming it explicitly prevents silent regressions.
