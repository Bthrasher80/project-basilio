# WN11-CC-000170 — Microsoft Accounts Must Be Optional for Modern Style Apps

**Date:** June–July 2026
**Stage:** Vulnerability Management — STIG Remediation
**Tools:** Tenable Vulnerability Management, PowerShell, Azure (Windows 11 VM)
**Benchmark:** DISA Microsoft Windows 11 STIG v2r7
**STIG-ID:** WN11-CC-000170 | **Vuln-ID:** V-253384 | **Rule-ID:** SV-253384r991589_rule
**Severity:** CAT III | **CCI:** CCI-000366 | **NIST 800-53:** CM-6b

## Objective
Remediate DISA STIG WN11-CC-000170, which requires the setting that allows Microsoft accounts to be optional for modern-style (Store) apps to be enabled. Confirm with an authenticated Tenable compliance scan.

## Problem Statement
Without this setting enabled, modern apps can compel users to sign in with a Microsoft account, tying enterprise activity to consumer cloud identities outside organizational control. Making Microsoft accounts optional keeps authentication within managed enterprise identity. CAT III, NIST CM-6b.

## Environment
- **Target:** Windows 11 Pro VM (`VirtualTest15`), private IP 10.0.0.10, Azure Cyber Range subscription
- **Scanner:** Tenable `LOCAL-SCAN-ENGINE-01`, authenticated credentialed scan
- **Audit policy:** DISA Microsoft Windows 11 STIG v2r7 (Windows Compliance Checks)

## Solution / Steps Taken
1. Confirmed the finding in the baseline authenticated scan — **Failed**.
2. Reviewed the Tenable Solution text: set `MSAOptional` to `1` under the System policy key.
3. Applied the fix via PowerShell (elevated):

```powershell
New-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "MSAOptional" -PropertyType DWord -Value 1 -Force
```

4. Verified the value persisted, then re-scanned — **Passed**.

## Validation and Testing
| Scan State | Registry Value | Audit Result |
|---|---|---|
| Baseline | key absent / `0` | **Failed** |
| After fix | `1` | **Passed** |

Full fix → revert → re-apply cycle demonstrated on WN11-CC-000315 as the representative sample; this control documented as remediation-confirmed. Scan timestamps in the Tenable History tab.

## Key Findings
- Registry path: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System`
- Value: `MSAOptional` (DWORD) — compliant when `1`
- Parent key exists by default on Windows 11, so no key creation was required.

## Security and SOC Relevance
Keeping Microsoft accounts optional preserves enterprise identity control — activity stays tied to managed accounts rather than consumer cloud identities, which matters for auditability, access revocation, and incident attribution.

## Challenges and How I Solved Them
This control's parent key (`...\Policies\System`) already exists on Windows 11, so unlike the CloudContent- and Search-based controls it did not require key creation. I still used `New-ItemProperty -Force` for consistency and to overwrite any pre-existing non-compliant value cleanly.

## Lessons Learned
Not every policy key needs to be created — some pre-exist. Using `-Force` uniformly across all fixes handles both cases (create-or-overwrite) without needing to branch logic per control.
