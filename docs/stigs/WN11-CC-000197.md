## Objective
Remediate DISA STIG WN11-CC-000197, which requires Microsoft consumer experiences (suggested apps, auto-installed content) to be turned off. Confirm with an authenticated Tenable compliance scan.

## Problem Statement
Windows consumer experiences auto-install third-party apps and suggested content from the Microsoft Store without administrator control. On a managed/enterprise asset this introduces unvetted software and unnecessary network activity. Disabling it enforces control over what software reaches the endpoint. CAT III, NIST CM-7a.

## Environment
- **Target:** Windows 11 Pro VM (`VirtualTest15`), private IP 10.0.0.10, Azure Cyber Range subscription
- **Scanner:** Tenable `LOCAL-SCAN-ENGINE-01`, authenticated credentialed scan
- **Audit policy:** DISA Microsoft Windows 11 STIG v2r7 (Windows Compliance Checks)

## Solution / Steps Taken
1. Confirmed the finding in the baseline authenticated scan — **Failed**.
2. Reviewed the Tenable Solution text: set `DisableWindowsConsumerFeatures` to `1` under the CloudContent policy key.
3. Applied the fix via PowerShell (elevated):

```powershell
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\CloudContent" -Force | Out-Null
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\CloudContent" -Name "DisableWindowsConsumerFeatures" -PropertyType DWord -Value 1 -Force
```

4. Verified the value persisted, then re-scanned — **Passed**.

## Validation and Testing

|---|---|---|
| Baseline | key absent / `0` | **Failed** |

Full fix → revert → re-apply cycle demonstrated on WN11-CC-000315 as the representative sample; this control documented as remediation-confirmed. Scan timestamps in the Tenable History tab.

## Key Findings
- Registry path: `HKLM\SOFTWARE\Policies\Microsoft\Windows\CloudContent`
- Value: `DisableWindowsConsumerFeatures` (DWORD) — compliant when `1`

## Security and SOC Relevance
Turning off consumer experiences reduces the endpoint's software attack surface and eliminates uncontrolled app installs — directly supporting the least-functionality principle a VM Analyst enforces across a fleet.

## Challenges and How I Solved Them
The `CloudContent` parent key did not exist by default. I created it with `New-Item -Force` before setting the value, since `New-ItemProperty` alone fails with a PathNotFound error when the parent key is absent.

## Lessons Learned
For policy keys that Windows does not create until a setting is configured, the remediation must build the key path first. Chaining `New-Item -Force` before `New-ItemProperty` makes the fix reliable regardless of the starting state.
