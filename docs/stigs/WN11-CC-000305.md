# WN11-CC-000305 — Indexing of Encrypted Files Must Be Turned Off

**Project:** Project Basilio — DISA STIG Remediation (LOGN Pacific Cyber Range Internship)
**Date:** June–July 2026
**Stage:** Vulnerability Management — STIG Remediation
**Tools:** Tenable Vulnerability Management, PowerShell, Azure (Windows 11 VM)
**Benchmark:** DISA Microsoft Windows 11 STIG v2r7
**STIG-ID:** WN11-CC-000305 | **Vuln-ID:** V-253409 | **Rule-ID:** SV-253409r958478_rule
**Severity:** CAT II | **CCI:** CCI-000381 | **NIST 800-53:** CM-7a

## Objective
Remediate DISA STIG WN11-CC-000305, which requires that indexing of encrypted files be turned off. Confirm with an authenticated Tenable compliance scan.

## Problem Statement
When Windows Search indexes encrypted files, plaintext content and metadata from those files are written into the search index — an unencrypted store. This partially defeats the purpose of file encryption by leaking indexed content to a location that may not carry the same protections. Disabling encrypted-file indexing keeps protected content out of the index. CAT II, NIST CM-7a.

## Environment
- **Target:** Windows 11 Pro VM (`VirtualTest15`), private IP 10.0.0.10, Azure Cyber Range subscription
- **Scanner:** Tenable `LOCAL-SCAN-ENGINE-01`, authenticated credentialed scan
- **Audit policy:** DISA Microsoft Windows 11 STIG v2r7 (Windows Compliance Checks)

## Solution / Steps Taken
1. Confirmed the finding in the baseline authenticated scan — **Failed**.
2. Reviewed the Tenable Solution text: set `AllowIndexingEncryptedStoresOrItems` to `0` under the Windows Search policy key.
3. Applied the fix via PowerShell (elevated):

```powershell
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Windows Search" -Force | Out-Null
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Windows Search" -Name "AllowIndexingEncryptedStoresOrItems" -PropertyType DWord -Value 0 -Force
```

4. Verified the value persisted, then re-scanned — **Passed**.

## Key Findings
- Registry path: `HKLM\SOFTWARE\Policies\Microsoft\Windows\Windows Search`
- Value: `AllowIndexingEncryptedStoresOrItems` (DWORD) — compliant when `0`

## Security and SOC Relevance
This control protects data confidentiality by preventing encrypted content from leaking into an unencrypted index — a subtle but real data-at-rest exposure that compliance scanning is specifically designed to catch.

## Challenges and How I Solved Them
The `Windows Search` policy key did not exist on the baseline build, so my first `New-ItemProperty` failed with a PathNotFound error. I created the parent key with `New-Item -Force` first, then set the value — the same key-creation pattern required for several other CloudContent/Policies-based controls in this set.

## Lessons Learned
Reinforced the pattern that policy keys absent by default must be created before values can be written. Building this into the standard fix (`New-Item -Force` then `New-ItemProperty -Force`) makes remediation idempotent and portable across assets in any starting state.
