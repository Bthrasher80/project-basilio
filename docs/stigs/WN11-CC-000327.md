**STIG-ID:** WN11-CC-000327 | **Rule-ID:** SV-253415r958420_rule

## Objective
Remediate DISA STIG WN11-CC-000327, which requires PowerShell transcription to be enabled. Confirm with an authenticated Tenable compliance scan.

## Problem Statement
PowerShell transcription writes a complete input/output transcript of every PowerShell session to a text log. Where script block logging captures the code, transcription captures the full session — commands entered and their results — providing a durable forensic record that survives even if an attacker clears in-memory history. Without it, interactive PowerShell activity can be difficult to reconstruct after an incident. CAT II, NIST AU-3.

## Environment
- **Target:** Windows 11 Pro VM (`VirtualTest15`), private IP 10.0.0.10, Azure Cyber Range subscription
- **Scanner:** Tenable `LOCAL-SCAN-ENGINE-01`, authenticated credentialed scan
- **Audit policy:** DISA Microsoft Windows 11 STIG v2r7 (Windows Compliance Checks)

## Solution / Steps Taken
1. Confirmed the finding in the baseline authenticated scan — **Failed**.
2. Reviewed the Tenable Solution text: set `EnableTranscripting` to `1` under the Transcription policy key.
3. Applied the fix via PowerShell (elevated):

```powershell
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\Transcription" -Force | Out-Null
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\Transcription" -Name "EnableTranscripting" -PropertyType DWord -Value 1 -Force
```

4. Verified the value persisted, then re-scanned — **Passed**.

## Key Findings
- Registry path: `HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\Transcription`
- Value: `EnableTranscripting` (DWORD) — compliant when `1`
- Pairs with WN11-CC-000326 (script block logging): together they provide both the executed code (EID 4104) and the full session transcript.

## Security and SOC Relevance
Transcription complements script block logging to give complete PowerShell visibility — code plus full session context. This directly supports incident response: after a suspected compromise, transcripts let an analyst reconstruct exactly what an attacker did in an interactive session, even if they attempted indicator removal (ATT&CK T1070). Enabling both controls is a deliberate, layered logging posture rather than a single checkbox.

## Challenges and How I Solved Them
Applied the established key-creation pattern (`New-Item -Force` then `New-ItemProperty -Force`) since the Transcription key was absent by default. Fix applied and validated on the first cycle.

## Lessons Learned
Controls are often designed to work in pairs. Script block logging (000326) and transcription (000327) are individually useful but together provide defense-in-depth for PowerShell visibility — recognizing those relationships is what turns a list of STIGs into a coherent logging strategy.
